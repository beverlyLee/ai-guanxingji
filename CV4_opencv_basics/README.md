# CV4 · 图像处理实战篇

> 正文：[`正文.md`](正文.md)（《扫信用卡号、找空车位、拼全景照：OpenCV 那几招能串起几个真项目？》）

把 CV1–CV3 讲过的基础（灰度化、直方图与阈值、形态学、轮廓、特征点与几何变换）串成三个能跑通的真项目：

| 项目 | 用到的知识 | 公开数据 |
|------|-----------|---------|
| 信用卡数字识别 | 灰度化 / Otsu 阈值 / 闭运算 / 轮廓+面积筛选 / 浅层分类器 | MNIST（ossci 镜像，脚本自动下载） |
| 停车位占用识别 | Otsu 阈值 / 开运算 / 轮廓+面积筛选 / 精确率·召回率·F1 | 脚本生成的停车场示意图（可换 PKLot） |
| 全景图像拼接 | SIFT / 比值检验 / 单应矩阵 / RANSAC | OpenCV 官方示例图 building.jpg（脚本自动下载） |

## 怎么跑

```bash
python code/experiment.py    # 产出 stats.json 与 figures_data/*.npz
python code/figures.py       # 从上面两个产物重生 figures/*.png
python code/qc_article.py    # 文章 QC：字数 / 黑名单词 / 破折号 / 粗体 / 数学占比 / 数字一致性
```

依赖见 `requirements.txt`。MNIST 与 building.jpg 会自动下载到 `data/`（MNIST 的 .gz 不入库），停车位场景为脚本现场生成，不需要下载。

## 本篇核心数字（全部由 `stats.json` 提供，正文与之逐项校验）

- MNIST：20000 张训练子集 / 单隐层 128 / 20 轮 → 测试准确率 0.9557
- 信用卡：Otsu 阈值 115，定位 16/16 位，识别对 15 位，卡面准确率 0.9375（错的那位是 3→9）
- 停车位：30 帧 × 12 车位，真占用 164，判对 162，误报 0，漏报 2 → P 1.0000 / R 0.9878 / F1 0.9939
- 全景拼接：关键点 4566 / 3866，比值检验后 2972 对，RANSAC 内点 2841（内点率 0.9559），内点平均重投影误差 0.141 px，与真值单应差距 0.03 px

## 一个诚实的说明

停车位场景用的是脚本生成的示意图，不是真实停车场数据（PKLot 官方下载地址在实验时已失效），所以那里跑出来的指标比真实场景漂亮。全景拼接的图 2 是用已知单应从图 1 变换出来的，因此 0.9559 的内点率是理想条件下的上界，真实拍摄通常在 30%–60%。这两点在正文里都写清了。
